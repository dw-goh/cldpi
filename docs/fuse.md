# FUSE (Filesystem in Userspace)
파일시스템을 커널이 아니라 일반 프로그램(유저 공간)에서 구현할 수 있게 해주는 다리 역할
커널 모듈 없이 유저 공간 프로그램으로 파일시스템을 구현할 수 있는 프레임워크

## 유저공간 파일시스템이 필요한 이유
- 개발 용이성: 커널 프로그래밍 없이 C, Python, Go, Rust 등 일반 언어로 파일 시스템 구현 가능
- 안정성: 유저공간 프로세스 크래시가 커널 패닉을 유발하지 않음
- 빠른 프로토타이핑: 커널 재컴파일 없이 파일시스템 로직을 즉시 수정/테스트 가능
- 라이브러리 활용: OpenSSL, libcurl, gRPC 등 유저공간 라이브러리를 자유롭게 사용 가능
- non-root 마운트: 일반 사용자도 fusermount를 통해 파일시스템 마운트 가능

## 주요 구성
- fuse.ko 모듈
  - 계층: 커널
  - 역할: VFS 요청을 /dev/fuse 디바이스를 통해 유저공간으로 전달
- libfuse (libfuse3)
  - 계층: 라이브러리
  - 역할: /dev/fuse와의 통신을 추상화, high-level/low-level API 제공
- FUSE 데몬
  - 계층: 유저공간
  - 역할: 실제 파일시스템 로직 구현(sshfs, ntfs-3g 등)
